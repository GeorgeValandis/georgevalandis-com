# Newsletter consent on ALL-INKL

This setup keeps the newsletter consent evidence on the existing ALL-INKL MySQL database while
keeping it separate from the cookie-notice log. The local tables store no raw subscriber email:
they store an HMAC of the normalized email, the MailerLite subscriber ID, status changes and
consent events. The website records the affirmative `Subscribe` action as a pending
`signup_requested` event; MailerLite's Double-Opt-in webhook records the later confirmation.

## 1. Create the tables

Run [`docs/newsletter-consent.sql`](/Users/georgiosavenidis/CascadeProjects/windsurf-project/homepage/docs/newsletter-consent.sql)
in the same MySQL database used by the consent log.

The tables are:

- `newsletter_subscriber`: current locally known state.
- `newsletter_consent_event`: append-only provider and manual events.
- `newsletter_suppression`: reserved for a separately documented erasure/blocking case.

An ordinary unsubscribe is recorded as `withdrawn`; it does not permanently block a later,
separately confirmed subscription.

## 2. Extend the server-only config

The existing server file is `/consent/config.php`. Add the values shown in
[`public/consent/config.sample.php`](/Users/georgiosavenidis/CascadeProjects/windsurf-project/homepage/public/consent/config.sample.php):

- `newsletter_webhook_secret`: the secret generated by MailerLite for the webhook.
- `newsletter_email_hash_salt`: a long secret used only for email HMACs.
- `newsletter_ip_hash_salt`: a separate secret used only when MailerLite sends an opt-in IP.
- `newsletter_admin_token`: a separate bearer token for the private withdrawal/export endpoints.
- `newsletter_form_id`: currently `Em4Az7`.
- `newsletter_consent_version` and `newsletter_privacy_version`: increment when the wording or
  privacy explanation changes.
- `mailerlite_api_token`: a MailerLite API token used only by the private withdrawal endpoint.

Never commit `consent/config.php` or place any of these secrets in frontend code.

## 3. Deploy the server endpoints

Deploy these public PHP files to the webspace:

- `/newsletter/webhook.php`
- `/newsletter/subscribe.php`
- `/newsletter/withdraw.php`
- `/newsletter/export.php`
- `/newsletter/_lib.php`

The subscribe endpoint accepts only a POST with an affirmative `subscribe_button` method and
stores only an HMAC of the normalized email, plus timestamp and a salted IP hash. The webhook
accepts only POST requests with a valid MailerLite `Signature` HMAC. The withdrawal and export
endpoints accept only POST requests with an `Authorization: Bearer ...` header using
`newsletter_admin_token`; they do not accept tokens in URLs.

## 4. Create the MailerLite webhook

In MailerLite, create one webhook pointing to:

`https://georgevalandis.com/newsletter/webhook.php`

Subscribe it to these events:

- `subscriber.created`
- `subscriber.updated`
- `subscriber.unsubscribed`
- `subscriber.active`

Copy the generated webhook secret into `newsletter_webhook_secret`. Verify in the MailerLite
account that Double Opt-in is enabled for form `Em4Az7` and that the opt-in evidence is available
there. The webhook is the source for provider confirmation and unsubscribe events. The browser-side
POST documents the user's affirmative Subscribe action, but it does not replace MailerLite's
Double-Opt-in confirmation.

## 5. Process a withdrawal request

When a person requests removal by email, send the address to the private endpoint from an
authenticated terminal or API client:

```bash
curl -X POST "https://georgevalandis.com/newsletter/withdraw.php" \
  -H "Authorization: Bearer YOUR_NEWSLETTER_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email":"person@example.com"}'
```

The endpoint looks up the address in MailerLite, sets the MailerLite subscriber to
  `unsubscribed`, and records a local `manual.withdrawal` event. It does not expose whether an
address is on the list to unauthenticated callers.

## 6. Verify the evidence

Use the private export endpoint with the requested email or MailerLite subscriber ID:

```bash
curl -X POST "https://georgevalandis.com/newsletter/export.php" \
  -H "Authorization: Bearer YOUR_NEWSLETTER_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email":"person@example.com"}'
```

The response contains the pseudonymous current record, the event history and any suppression
record. It never returns the raw email because the address is supplied only for the authenticated
lookup and converted to the local HMAC.

## 7. Retention and erasure

This implementation intentionally leaves the retention period configurable. Before production,
document the concrete retention period or criteria in the Privacy Statement. Keep ordinary
withdrawal, proof, suppression and full erasure as separate operations. A full erasure request
must also be handled in MailerLite; a local HMAC remains personal data and is not automatically
anonymous.
